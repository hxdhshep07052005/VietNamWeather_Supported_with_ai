\chapter{Experimental Evaluation and Results}
\label{ch:evaluation}

This chapter reports what has been implemented and verified in VietForecast. The evaluation focuses on route comparison, vehicle-specific risk, backend and spatial performance, grounded assistant behaviour, and the main web interfaces. Results describe the tested deployment and scenarios; they are not presented as guarantees for every journey or provider condition.

\section{Evaluation Scope and Test Setup}
\label{sec:experimental_setup}

The tests used the same stack as the application: React/Vite and MapLibre GL in the browser, Fastify 5 and TypeScript for the API, PostgreSQL 16/PostGIS 3.4, Redis 7, Directus, and the Node.js worker in Docker Compose. k6 and Autocannon generated concurrent API traffic. Route checks covered northern mountain, central coast, and north--south corridors, with rain, wind, fog, and stale-data cases. The main measures were route risk, severe checkpoints, travel-time and distance overhead, query latency, API throughput, cache hits, tool accuracy, citation coverage, and usability.

The same weather can produce different warnings for cars and motorcycles. In the tested crosswind and rain scenario, the car remained at Caution while the motorcycle reached High risk. This confirms that the vehicle profile is applied during checkpoint assessment and route comparison.

At 100,000 station records, the indexed query completed in 11.40~ms versus 420.50~ms for a sequential scan. This confirms that PostGIS/GiST supports the route planner's spatial lookup target in the tested dataset.

\subsection{Fastify API, Redis, and Worker Reliability}
The Fastify load test reached 2,485 requests per second with no HTTP 5xx responses. Median latency was 4.2~ms, with $p_{95}=12.8$~ms and $p_{99}=21.5$~ms. Redis achieved a 92.4\% hit ratio on frequently requested weather and route data and reduced repeated database reads.

The worker tests also completed the main failure cases. After the active worker was stopped, a standby worker acquired the expired PostgreSQL lease. During provider errors, the circuit breaker opened after three failures, served fallback data without repeated upstream calls, and returned to Half-Open after the cooldown period.

\section{Achievement Against Project Objectives}
The evaluation confirms that the project delivered the core objectives within the scope defined in Chapter~1:
\begin{itemize}
    \item Weather lookup, map exploration, forecasts, and freshness states are available in the web application.
    \item Route alternatives can be calculated and compared using distance, duration, vehicle type, weather evidence, and checkpoint warnings.
    \item The Fastify, PostgreSQL/PostGIS, Redis, Directus, worker, and MapLibre stack is integrated and tested in Docker Compose.
    \item Session protection, worker failover, circuit breaking, spatial indexing, and API validation were exercised through automated tests and failure scenarios.
    \item The assistant supports grounded tool calls and a deterministic fallback; it remains an optional feature beside the map and route planner.
    \item The main user-facing screens and account, weather, route, and quota flows are implemented and demonstrated.
\end{itemize}
