\chapter{Conclusion and Future Work}
\label{ch:conclusion}

This chapter summarizes the implemented VietForecast web application, confirms the main objectives, and states the current limits and next steps.

\section{Summary of Project Achievements}
\label{sec:summary_achievements}

VietForecast combines weather data, an interactive map, and route comparison in one web application. The main achievements are:

\begin{itemize}
    \item[-] A vehicle-aware risk engine evaluates rain, wind, temperature, visibility, storms, and alerts at route checkpoints.
    \item[-] The route planner uses OSRM, ETA-based sampling, PostGIS weather lookup, and a balanced score to compare Fastest, Shortest, and Weather-Safer routes.
    \item[-] The TypeScript monorepo integrates React/Vite, MapLibre GL, Fastify, Directus, PostgreSQL/PostGIS, Redis, and a Node.js ingestion worker through Docker Compose.
    \item[-] The worker normalizes provider data, detects stale observations, uses leases and circuit breakers, and refreshes the cache.
    \item[-] The assistant uses grounded tools and a deterministic fallback, while the map, weather pages, route planner, accounts, saved data, and quota views remain the core user experience.
    \item[-] The tested interface achieved a SUS score of 84.6/100 (Grade A).
\end{itemize}

\section{Current Technical Limitations}
\label{sec:limitations}

\begin{itemize}
    \item[-] Weather station coverage is uneven in remote mountains and offshore areas. Interpolation and forecast grids can miss small, fast-forming hazards.
    \item[-] OSRM uses available road geometry but does not receive every live closure, landslide, flood, or construction update from road authorities.
    \item[-] Gemini introduces network latency and usage cost. The deterministic fallback covers supported requests when the provider is unavailable.
    \item[-] Dynamic weather lookup and rerouting require an internet connection; full offline navigation is not implemented.
\end{itemize}

\section{Future Research and Development Roadmap}
\label{sec:future_work}

\subsection{Short-Term Roadmap}
\begin{itemize}
    \item[-] Add a mobile client with background GPS, geofenced weather alerts, and voice guidance.
    \item[-] Support crowdsourced reports for flooding, landslides, and other road hazards.
\end{itemize}

\subsection{Medium-Term Roadmap}
\begin{itemize}
    \item[-] Provide offline route and forecast packages for areas with weak connectivity.
    \item[-] Explore on-device assistant models and computer-vision input from traffic cameras.
\end{itemize}

\subsection{Long-Term Roadmap}
\begin{itemize}
    \item[-] Connect official hydrometeorological and road-status services.
    \item[-] Extend the model to multimodal transport and spatio-temporal weather-risk forecasting.
\end{itemize}

\section{Concluding Remarks}
\label{sec:closing_remarks}

The project demonstrates that a focused web application can combine spatial weather evidence with route planning in a practical interface. Its tested results show that the core stack, route-risk workflow, data pipeline, grounded assistant, and user-facing features work together within the defined scope. Further deployment requires better road-status feeds, denser observations, mobile and offline support, and continued validation with real users and journeys.
